# 修正方針 — DICE の路線転換

作成: 2026-08-21。既存の `godot_project/art/PIPELINE.md` は「明るい卓上・羊皮紙・全員少女」
を前提に書かれているが、その前提は破棄した。この文書が現時点の方針。
コードの構造（マス種別・盤の機構・`art/` のスロット命名）は変更しない。
**意味と見た目だけを読み替えて、既存の枠に埋め込む。**

未確定の論点は「未決」として明記する。決定済みとして書かれていない限り、
まだ何も固まっていないと読んでほしい。

---

## 1. ジャンルの転換

一般ゲーム市場ではなく、**エロトラップダンジョン**路線に転換する。

理由（実測・比較の詳細は会話ログ参照）:

- 既存の `art/cg/` スロットは元々「敵ごとの勝敗CG」という構造で、このジャンルの型と
  既に一致していた。作り直しではなく、空いている枠を埋める話になる
- このPCで日本語のみ・NSFW前提で完結できる市場は、英語化前提の一般市場より
  到達難度が低い。詳細な比較は会話ログの「普通のゲーム市場とNSFW市場」を参照
- `art/` のスロットは**ファイルが無ければ静かに隠れる**設計になっている。
  CGを抜くだけで全年齢版が作れるため、両対応は後からでも安く実現できる

### コンセプト

> **運命に足を取られる。**
> すごろくは「行き先を選べない」遊び。このジャンルの核も「避けられない」こと。
> 機構とテーマが同じことを言っているのが本作の芯。

## 2. ゲージ統合（確定）

HPと第二ゲージを分ける案は破棄。**HPをそのまま「昂り」として扱う。**

### 実装方針

内部データは今のHP（減っていく数値）をそのまま使う。**表示だけ
`最大値 − HP` を昂りとして描画する。** ダメージ計算・状態異常・敵AI・
瀕死判定（`HP ≤ 35%` → `昂り ≥ 65%`）は書き換えない。

### 敗北条件（確定）

**昂りがMAXの状態で、敵の直接攻撃を受けると敗北。** MAX自体では敗北しない。

既存の敵データの攻撃条件がそのまま難度カーブになる:

| 型 | MAX到達後の猶予 |
|---|---|
| `cell` / `die`（条件付き攻撃） | 猶予がある。立て直せる |
| `guaranteed`（毎ターン攻撃） | 次のターンで終わる |

弱い敵ほど猶予が長く、強い敵ほど即死に近い。追加実装なしで敵の格が
猶予時間として表現される。

### 罠マスの扱い（確定）

**罠はMAX時でも通常と同じ挙動。** 特別な追加効果は付けない。

### 命名の分離（確定）

プレイヤー側とダンジョン側で命名のトーンを変える。

| 系統 | 命名 |
|---|---|
| プレイヤー側の手札・バフ | 通常の名前のまま（標準・攻撃・防御・盾など） |
| 敵の攻撃・罠 | 性的な方向に寄せる |

罠の読み替え案（**仮称**。最終決定ではない）:

| 現行 | 改訂案 | 効果 |
|---|---|---|
| 毒 | 疼き | 継続的に昂りが上昇 |
| 凍結 | 拘束 | 行動不能。その間も昂りが上がり続ける |
| 装甲 | 抵抗 | 昂りの上昇を軽減 |
| 手負い | 過敏 | 受ける昂りの上昇が増える |
| 盾+1 | 平静 | 昂りが下がる。盤上で唯一の救い |
| charge | 蓄積 | 溜まるほど次の罠の上昇量が大きい |
| 斬撃路 | 激発 | 昂りが大きく上昇 |
| 疾走 | 誘導 | 強制的に複数マス進む |

## 3. 勝利条件の転換（検討中・未確定）

**敵を倒すことをゴールにしない案が出ている。** 撃破が目標だと彼女が加害側に
なり、「耐えて切り抜ける」という構図が崩れるため。

### 検討中の形

- 各層の盤に出口を置き、到達すれば突破。**敵HPを廃止**
- 攻撃ダイスは「ダメージ」ではなく「**振り払う**」（敵を押し戻す／怯ませる）
  に読み替える。防御・標準はそのまま
- 敵は倒せないが遠ざけられる、という距離と時間を稼ぐ遊びにする

### 未決 — ここは要判断

**敵は盤上を動くか、盤の外から一定間隔で攻撃するか。**

| 案 | 緊張感 | 実装コスト |
|---|---|---|
| 盤上を動く（追われる） | 最大 | 中〜大。移動AIが新規実装になる |
| 盤外から一定間隔で攻撃 | 中 | 小。今の構造にほぼ乗る |

**出口までの到達条件をどう定義するか。** 今の盤は周回する構造
（`帰`＝左上・右上・右下・左下のマスがある）なので「1周したら出口が開く」
という形も既存構造の流用で実現できるが、これも未決。

**この転換を実行するかどうか自体、まだ確定ではない。** 現状の
「敵を倒す」構造のまま昂りゲージだけ載せる、という選択肢も残っている。

## 4. 敵 — 全員モンスターに変更（確定）

前案（敵7体も可愛い女の子）は破棄。**全員を人外にする。**

理由: このジャンルの王道に合わせること、そして既存8体で最大の欠陥だった
「シルエットが全部同じで敵が敵に見えない」問題を同時に解決するため。

「大きさ」は立ち絵が枠に fit されるため、**キャンバスではなく構図の寄りで
作る**。層が上がるほど構図を寄せれば、敵が画面に迫ってくる体感になり、
コード変更なしで難度カーブが絵に出る。

具体的な7体のシルエット案・配色案は会話ログの設計書ドラフトを参照。
**名称・詳細仕様はすべて仮**、確定していない。

## 6. UI — 「石の迷宮」路線（方向は固まりつつあるが細部は仮置き）

過去2案を差し戻した末に、3案目の方向で合意に近づいている状態。
**まだ「これで確定」の返事はもらっていない。**

### 差し戻された前提

- 1案目「貴族の賭博卓」（木の卓・真鍮・フェルト）— 却下。彼女に余裕がある
  側の画面で、ジャンルが要求する「追い詰められる画面」と逆
- 2案目（額装された肖像プレート）— 却下。「額縁や貴族の卓上などの前提は
  あなたが勝手に作ったもの」という指摘どおり、デザイナーが持ち込んだ
  道具立てで、ゲームの前提（迷宮の中にいる）から出てきたものではなかった

### 現行の仮置き（3案目）の骨子

- **盤は卓上のボードではなく、彼女が立っている迷宮の床そのもの**
- 彼女は額装しない。床に立ち、接地影を持つ。敵と同じ空間にいる
- 敵は枠なし。部屋奥の闇から出てくる（今は光る眼だけのプレースホルダ）
- 状態（昂り）は**箱入りのバーではなく、部屋の光の色**で伝える。
  冷たい青緑（平静）→ 薔薇色（限界）に環境ごと転ぶ
- 罠マスは床の刻印で予告する。**暖色＝彼女を蝕むもの、寒色＝安全**という
  反転した色彩体系
- フォントはドット字（DotGothic16）を廃止し、明朝体に変更する方向

### 仮置き版で残っている未解決の課題

- 遠近感を強くつけると盤の奥の列が小さくなり、すごろくの経路として
  読みにくくなる可能性がある。臨場感と可読性のトレードオフが未調整
- セリフ表示位置が盤の下端と干渉している
- ダイスと盤の最下段の間隔が詰まりすぎている
- 全体の明るさがまだ暗く、判別ぎりぎり

## 8. 技術メモ — 画像生成パイプライン（参考）

デザインの決定とは独立した、再利用可能な技術知見。

- **Chroma v50 fp8-scaled**（`chroma-unlocked-v50-fp8-scaled.safetensors`、
  8.29 GiB）は、旧 bf16 版 v50 の代替として導入済み。同じ絵柄の傾向
  （シード間の振れ幅が大きく、個性が出やすい）を保ったまま軽量
- **Chroma1-HD**（`Chroma1-HD-fp8mixed.safetensors`）も別途保持。
  1枚あたりの完成度は高いが、シード間の差が小さく「顔が似通う」傾向がある。
  用途によって使い分ける
- ドット化の後処理: BOX縮小(block=4) → 48色程度に減色 → NEAREST拡大、が
  拡散だけでドット化するより顔の保存率が高い
- 透過切り抜き: 単純な色域抜きではなく、**画像の端から境界フラッド
  フィル**で背景だけを抜く方式が、衣装内側の白を壊さない
- 表示検証は必ず**実際のゲーム内表示サイズ**（立ち絵なら274×412）で行う。
  制作解像度のまま見て判断すると、非整数縮小やフィルタの影響を
  見誤ることが複数回あった

これらの生成スクリプトは現時点でこのリポジトリの外（作業PC上の一時
ディレクトリ）にのみ存在する。再利用するには `tools/` 配下への
persist が別途必要（未実施）。

## 9. 優先順位（旧`PIPELINE.md`の順序は無効）

`MANIFEST.md` のP0/P1/P2は「壊れて見えるか」の優先度であり、
方針転換後に効く順ではない。現時点で妥当と考えられる順序:

1. §3（勝利条件）を確定させる — ここが決まらないと敵AI・UIの設計が固まらない
2. 昂りゲージの実装（§2は確定事項なので着手可能）
3. UI配色・フォントの差し替え（`Main.gd`の定数置換が中心。効果に対して費用が小さい）
4. 主人公の再設計 + 一貫性のある生成手法の確立
5. 敵7体（モンスター）の立ち絵
6. 罠マスの見た目
7. 背景・ロゴ
8. 決着CG
9. 音

1が終わっていないため、2以降も設計変更の影響を受ける可能性がある。
