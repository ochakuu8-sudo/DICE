# 生成アートの作り方（ComfyUI 前提）

`README.md` は**スロットの仕様**（どのファイル名がどこに出るか）、
`MANIFEST.md` は**残りの一覧**。この文書はその手前、
**何をどの順で、どう作って、どう入れるか**の設計です。

差し替え箇所の設計はすでに済んでいます。コードを触る必要はなく、
**決められた名前で `art/` に置くだけ**で反映されます。画面に出ている
マゼンタの「NO ART」は、そのスロットが空だと分かるように出しているもので、
そこに置けばそのまま絵になります。プレースホルダは自分の
**スロットID と表示サイズ**を書いているので、迷ったら実機を見れば答えが出ます。

---

## 1. 順番 — ストアで見られる画を最短で作る

`MANIFEST.md` の P0/P1/P2 は「無いと壊れて見えるか」の優先度で、
**「ストアページが良く見えるか」の順ではありません**。実際に効く順はこうです。

| # | 作るもの | 枚数 | なぜ先か |
| --- | --- | --- | --- |
| 1 | `ui/logo_default.png` | 1 | **ストアの第一印象そのもの**。無いとゲーム名が本文フォントの文字列で出る |
| 2 | `bg/scene_title.png` | 1 | タイトルのキービジュアル。ロゴとセットで1枚の画になる |
| 3 | `stage/knight_idle.png` | 1 | 戦闘画面の左。以降すべての絵の**基準スタイル**になる |
| 4 | `bg/scene_default.png` | 1 | **これ1枚で全画面の下地が埋まる**。以降の背景は上書きしていくだけ |
| 5 | `stage/stray_idle.png` | 1 | これで戦闘スクショが1枚完成する |
| 6 | 残り6体の `stage/*_idle.png` | 6 | マゼンタが全部消える（P0 完了） |
| 7 | `face/*_node.png` 7枚 | 7 | マップ画面が「作られた画面」に見えるようになる |
| 8 | `bg/scene_battle.png` `scene_map.png` | 2 | 画面ごとの差が出る |

**ここまで20枚**で、ストアに載せる3〜4枚のスクリーンショットは揃います。
CG・被弾アニメ・瀕死差分はその後で構いません。

`MANIFEST.md` の **P0 は立ち絵8枚だけ**です（かつて P0 にあった決着CG
22枚は P2 に落ちました。§7 参照）。**P0 を埋めればマゼンタは1枚も
出なくなります。**

## 2. 実測サイズ — 何を作るか

「推奨サイズ」ではなく、**実際に画面のどこに何ピクセルで出るか**です。
論理解像度 1024×576 での値で、ウィンドウが大きければ等倍で拡大されます。

### `stage/` 立ち絵

| | 表示枠（1024×576時） | 比 |
| --- | --- | --- |
| 自機（左） | 274 × 412 | 0.67 |
| 敵（右） | 234 × 424 | 0.55 |

敵枠の高さは以前その敵の説明文の行数で変わり、特性の多いボスほど小さく
なっていました（234×290）。いまは**下限236pxの床**があり、説明文の側が
5行で打ち切られるので、**どの敵もほぼ同じ枠**に立ちます。
**fit（はみ出さずに収める）**なので、縦横比が合わなくても切れません。余白が出るだけです。

- 作画: **800 × 1200（2:3）透過PNG**
- 表示は最大でも 274×412 なので、2倍強の余裕があります。4K で遊ばれても持ちます
- 背景は完全透過。後ろのパネルは UI の一部です
- 足元を枠の底に合わせる必要はありません（中央に fit されます）

### `bg/` 背景

- 作画: **1920 × 1080（16:9）不透過**
- **cover（画面を埋めて、はみ出しは切る）**なので、
  16:9 でないウィンドウでは**上下または左右が切れます**。
  主題を中央 80% に収めてください
- 画面上には盤・カード・パネルが重なります。**中央は空けて、
  情報量は四隅と周辺に**。真ん中に主役を置くと UI に埋もれます

### `cg/` 全画面イラスト

- 作画: **1920 × 1080（16:9）不透過**
- fit なので切れません。タップで消えるまでの数秒間、画面全体を占めます

### `ui/` — インターフェイスの部品

いまのところ 1 枚だけです。

| ファイル | 出る場所 | 仕様 |
| --- | --- | --- |
| `ui/logo_default.png` | タイトル画面の最上部 | **横長・透過PNG / 目安 900 x 260** |

表示枠は**カード幅いっぱい × 高さ108**で **fit**（切れません）。
無ければゲーム名が文字で出るだけなので、壊れはしません。
ただしストアページで最初に映る要素なので、実質必須です。
**暗い背景にも明るい背景にも乗る**よう、縁取りか影を持たせてください。

### `face/` マップ顔 ← **ここだけ注意**

- 作画: **256 × 256 透過PNG**
- ただし**表示枠は 54 × 42 の横長**で、しかも **cover（切る）**です。
  正方形で作ると**上下がばっさり切られます**
- **顔・主題を中央の 256 × 200 の帯に収めてください**。
  頭頂やアゴが切れて問題ないなら気にしなくて構いません

## 3. スタイルを固定する — 「安く見えない」ための本体

生成物が安く見える原因はほぼ**バラつき**です。8体のキャラが別々の絵柄・
別々の光・別々の色で並ぶと、1枚ずつの出来が良くても商品に見えません。
先に**1枚を基準として完成させ、残りを全部それに寄せる**のが要点です。

### 3.1 ゲーム側のパレットに合わせる

この game は「暗いダンジョン」ではなく**明るい卓上**として作ってあります。
生成側でもそれに寄せないと、絵と UI が喧嘩します。

| 役割 | 色 |
| --- | --- |
| 線・輪郭 | `#2A2320`（黒ではなく焦げ茶） |
| 紙・パネル | `#FFF7E6` |
| 卓の地色 | `#F7EDD6` → `#DFCCA2`（上が明るい） |
| 敵の赤 | `#C2453A` |
| 盾の青 | `#2E7BD6` |
| 金 | `#F2B33D` |

プロンプトに入れる形容としては、
**太い焦げ茶の輪郭線 / フラットなセル塗り / 暖色の羊皮紙系パレット /
影は少なく、明るい面を広く** あたりです。
コマの上に置く駒（token）が濃色なので、**キャラは明るい面を多く持つ方**が
画面全体で締まります。

### 3.2 固定するもの（1体目を作ったら二度と変えない）

- チェックポイント／LoRA
- サンプラー・ステップ数・CFG
- 解像度
- **スタイル指定の文字列**（プロンプトの後半ブロックをまるごと定型化）

キャラ固有の記述は**プロンプトの前半だけ**に置き、後半のスタイルブロックは
全キャラ共通で 1 文字も変えない、という運用にしてください。

### 3.3 絵柄を揃える手段

テキストだけで 8 体揃えるのは無理があります。どれか一つは使ってください。

- **IPAdapter などの画像参照**に 1 体目の完成品を渡し、
  以降のキャラ生成でスタイル参照として固定する（最も効きます）
- スタイル LoRA を 1 つ選んで固定する
- 8 体を**同じシードの近傍**でまとめて回し、当たりだけ採用する

> ノード名・モデル名は環境と時期で変わります。ここに挙げたものは
> 「この役割のノードを探してください」という指示として読んでください。

### 3.4 同一キャラの状態差分（`idle` → `hit` / `down`）

**text2img で作り直してはいけません。**別人になります。

完成した `idle` を入力に、

- **img2img を低 denoise（0.3〜0.45 目安）**で振る
- または ControlNet（openpose 等）でポーズだけ変える

`hit` は被弾の一瞬、`down` は HP35% 以下の立ち方です。
`idle` からの小さな崩しで足ります。

## 4. 透過の作り方

RGBA を直接生成させるのは不安定です。**不透過で生成 → 切り抜き**が確実です。

1. 単色背景（白 or 明度差のあるグリーン）で生成する
2. 背景除去ノード（RMBG 系、InSPyReNet、SAM 系のいずれか）で alpha を作る
3. **縁の色被りを確認する**。緑背景で抜くと緑のフチが残ります。
   気になるなら白背景で抜く方が安全です

Godot 側の import 既定は `process/fix_alpha_border=true` なので、
半透明部分の縁のにじみはある程度吸収されます。それでも
**1〜2px のハロー**は目立ちます。等倍で確認してください。

## 5. 容量設計 — ここが一番の罠

**先に読んでください。後から気づくと作り直しになります。**

Godot の画像 import 既定は**可逆（`compress/mode=0`）**です。
1920×1080 のイラストは可逆だと **1枚 2〜4MB**。`MANIFEST.md` の
CG 22枚 + 背景 10枚を可逆で入れると、それだけで **80〜100MB** になります。

現状の `index.pck` は **6MB**。ここに 100MB を足すと:

- **Web ビルドが実用外**になります（`index.wasm` の 39MB は
  `sw.js` がキャッシュしますが、**`index.pck` は毎回フル取得する設計**です）
- git 履歴が膨らみます（`.git` はすでに 114MB）

### 対策（どれも必須ではなく、選択）

1. **`cg/` と `bg/` を非可逆 import にする。**
   `.import` の `compress/mode=1`（lossy WebP）+ `compress/lossy_quality=0.8` 程度。
   1920×1080 のイラストが **200〜400KB** になります。
   32枚でも 10MB 前後に収まります。
   透過も保持されるので `stage/` `face/` にも使えます
2. **`sw.js` に `index.pck` もキャッシュさせる。**
   ただし現状「pck は毎回新鮮に取る」という設計は意図的（デプロイが即反映される）
   なので、キャッシュするならデプロイのたびに `CACHE_NAME` を上げる運用とセットです
3. **書き出しを毎回コミットしない。**
   リリース時だけ `index.pck` を更新する

**まず 1 だけやれば足ります。** 実際にアートを入れ始める前に、
1枚テストして pck の増分を測ってください。

## 6. 取り込み手順

```
1. ComfyUI で書き出す
2. godot_project/art/<category>/ に正しい名前で置く
3. Godot エディタで一度プロジェクトを開く   ← 必須
4. 生成された *.png.import を一緒にコミットする
5. python3 tools/art_manifest.py            ← 進捗が更新される
6. 書き出す
```

**手順 3 を飛ばすと絵が出ません。** ローダーはディスク上のファイルではなく
**import 済みリソース**の有無を見ています。エディタを開いていない
ファイルは、ファイルが存在していても書き出しに含まれません。

アニメーション（`_0`, `_1`, …）は**0 から連番が途切れないこと**。
抜けたところでクリップが終わります。`<actor>_<state>.png` が単体であれば
それが優先され、1フレームのクリップとして扱われます。

## 7. 決定済みのコード側の判断

生成の無駄を減らすため、以下は**すでにコードに入っています**。

### 7.1 CG が無い戦闘は演出ごと飛ばす（済）

決着 CG が無いと全画面にマゼンタが出ていたため、CG 22枚が P0 でした。
`_play_scene` が**絵の無い決着では演出を飛ばす**ようになったので、
CG は **P2** に落ちました。回想（ギャラリー）の解放記録は絵の有無に
関係なく残るので、**後から CG を足せば、すでに遊んだぶんも埋まります**。

### 7.2 敵の「瀕死」立ち絵を表示する（済）

敵の `down` はどこからも表示されていませんでした（自機だけが使用）。
自機と同じ規則——**HP35%以下で `down`、無ければ `idle` に落ちる**——で
敵も切り替わるようになったので、`*_down.png` 7枚は無駄になりません。

## 8. まとめ — 最初の1回にやること

1. `cg/` `bg/` の import を非可逆にする方針を決める（§5）
2. **`stage/knight_idle.png` を 1 枚、納得いくまで作る**
3. その 1 枚を**スタイル基準**として固定し、以降すべてを寄せる
4. §1 の順で 20 枚まで進める

2 が一番重要です。ここで決まった絵柄が、残り 87 枚すべてを縛ります。
